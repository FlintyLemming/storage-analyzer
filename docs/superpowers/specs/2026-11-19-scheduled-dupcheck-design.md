# 定时扫描后自动检查重复项 设计文档（短）

日期：2026-11-19
状态：待确认
基于：[2026-11-17-duplicate-check-design.md](2026-11-17-duplicate-check-design.md)（本次取消其中"定时扫描后自动跑重复检查"这条非目标）

## 意图

重复检查也能定时自动跑，不用每次手动点。用户的决定：**只有一个计划任务**，在定时扫描的设置里加一个勾选项"扫描完成后检查重复项"，勾上后每次定时扫描成功就接着检查这次扫描的结果。

## 目标 / 非目标 / 反目标

- 目标：勾选后，定时扫描成功 → 立即对这次新扫描做重复检查，进度、取消、历史记录与手动检查一致。
- 非目标：给重复检查单独排时间；手动"新建扫描"后自动检查（勾选只影响定时任务）。
- 反目标：
  - 上一次任务（扫描或检查，手动或定时）没结束时又开始新的扫描或检查。
  - 扫描失败 / 被取消后还去检查（会查到旧结果）。
  - 扫描和检查之间的空档被别的任务插进来，导致检查被跳过。

## 方案

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A（选用）** | 定时任务进程拿到锁后，先扫描、成功后在**同一个进程、不放锁**的情况下接着检查 | 中间没有空档；crontab 行不变，开关在运行时读设置 |
| B | 扫描结束后再拉起一个独立的 `dupcheck` 进程 | 扫描放锁到检查拿锁之间，用户手动点"新建扫描"会插进来，检查被跳过 |
| C（已排除） | crontab 写两行，扫描、检查各定时间 | 用户已决定只要一个计划任务；两个时间撞上必有一个被跳过 |

## 设计

**设置**：`Settings` 新增 `scheduleDupCheck`（bool，默认关），存为 `schedule_dupcheck`。crontab 行保持 `scan --trigger schedule` 不变，所以改这个开关不需要重写 crontab。

**定时任务流程**（`runner.RunScheduled`）：

1. 拿锁；拿不到（已有扫描或检查在跑）→ **整次跳过**（既不扫描也不检查），记日志。和现在定时扫描撞上任务时的行为一致。
2. 读设置，决定这次是否接着检查。
3. 扫描（与现在相同，含按保留次数清理旧结果）。失败或被取消 → 不检查，结束。
4. 若开启、且没收到取消信号 → 对刚完成的扫描做重复检查，`trigger` 记为 `schedule`。
5. 全程持有同一把锁，结束才释放。

**取消**：扫描阶段点"取消扫描" → 扫描取消，不再检查；检查阶段点"取消检查" → 检查记为已取消，已算过的校验值留在缓存里。NAS 关机 / 应用停止 → 现有 `init-stop` 发 SIGTERM，同样处理。

**界面**：

- 设置对话框"定时扫描"下方，非"关闭"时显示勾选框"扫描完成后检查重复项"和提示：首次检查可能要几个小时，之后通常几分钟到几十分钟，期间硬盘较忙。
- 保存提示：`设置已保存：每天 03:00 自动扫描并检查重复项`。
- 进度条：定时扫描阶段显示 `· 定时任务，完成后检查重复项`。
- 页面开着时从扫描切到检查：前端看到任务从"扫描"变成"检查"（中间一直在运行）时，按"扫描完成"处理一次——提示扫描完成并切到新结果，然后继续显示检查进度。

**测试**：`RunScheduled` 覆盖：开关关 → 不检查；开关开 → 检查完成且 `trigger=schedule`；锁被占 → 整次跳过、不新增扫描记录；扫描失败 → 不检查；收到取消 → 不检查。设置读写覆盖新字段。
