# 重复文件 / 文件夹检查 设计文档

日期：2026-11-17
状态：待确认
基于：[2026-11-16-qnap-storage-analyzer-design.md](2026-11-16-qnap-storage-analyzer-design.md)

## 1. 意图

在已有的扫描结果上找出**内容完全相同**的文件和文件夹，帮助在 95% 已满的数据卷上找到可以释放的空间。

列表规则（用户原话的落地）：

- 两个文件夹里的所有内容都相同，就只列文件夹，而且一路向上合并，列出**最大**的那一层相同文件夹；被它包含的相同子文件夹、相同文件不再单列。
- 没有被相同文件夹包含的重复文件，单独列出。
- 文件夹和文件混在一起，按大小从大到小排列。

## 2. 目标 / 非目标 / 反目标

**目标**
- "相同"必须经过**完整内容校验**（全文 SHA-256），可以放心据此删除文件。
- 文件夹相同 = 里面的**文件名、子文件夹结构、每个文件的内容都一致**；文件夹自己的名字可以不同（`Photos` 与 `Photos 副本` 可以相同）。
- 重复检查是一个**单独的、手动发起**的后台任务，挂在某一次扫描结果上，有进度、可取消。
- **校验值缓存**：第二次及以后的检查只读取新增或变化过的文件。

**非目标（本次不做）**
- 删除 / 移动 / 替换为硬链接等任何修改操作（工具仍然只读）。
- ~~定时扫描后自动跑重复检查。~~（已由 [2026-11-19 设计](2026-11-19-scheduled-dupcheck-design.md) 取消这条非目标）
- "只看内容、不管文件名"的文件夹比较；"90% 相同"之类的近似文件夹。
- 跨两次扫描的对比。

**反目标（即使能跑也算失败）**
- 把内容不同的文件 / 文件夹报成相同（哪怕只差中间几个字节）。
- 检查期间拖慢 NAS：读几百 GB 时把 NAS 的页缓存冲掉、或和扫描同时压硬盘。
- 跑了几个小时被取消 / 重启后，下次一切从头再读。
- 列表被系统自动生成的缩略图、`.DS_Store` 之类刷屏，或者因为它们把本该相同的文件夹判成不同。

## 3. 约束

- 继承原设计的全部约束：J3455、HDD RAID、无常驻进程、静态 Go 二进制、纯 Go SQLite、扫描结果目录仅 root 可读。
- 现有扫描只读元数据，不读文件内容；扫描结果里没有 inode、ctime、文件内容摘要。
- 扫描结果是历史快照，检查发生在扫描之后，文件可能已经变了。
- J3455（Goldmont）支持 SHA 指令，Go 的 `crypto/sha256` 会用上，瓶颈在硬盘而不是 CPU。

## 4. 方案选择

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A（已选）** | 独立 `dupcheck` 任务 + 跨次检查的校验值缓存 | 第一次可能数小时，之后通常几分钟到几十分钟；多一个缓存库（每个算过的文件约 100 字节） |
| B | 独立任务，不带缓存 | 更简单，但每次检查都把所有候选文件重读一遍 |
| C（已排除） | 扫描时顺便算校验值 | 每次定时扫描都要读几百 GB，违背"单独手动发起" |

比对严格度另行讨论过：抽样比对（头 / 中 / 尾各取一段）几分钟出结果但不能保证正确，**用户选择了全量校验**。

## 5. 判定规则

### 5.1 参与比较的条目

对扫描结果里的每个条目确定一个"内容记号"（token）：

| 条目 | token |
|---|---|
| 普通文件，大小 > 0，经完整校验与别的文件相同 | `F(size, sha256)` |
| 普通文件，大小 > 0，没有任何文件与它相同（大小独一无二、或快速比对 / 完整校验后落单） | 唯一（不需要算完整校验值） |
| 大小为 0 的普通文件 | `E`（参与文件夹结构比较，但自己不作为重复文件列出） |
| 符号链接 | `L(链接目标)`，检查时 `readlink` 读取；读不到则唯一 |
| 硬链接重复条目（扫描里 `FlagHardlinkDup`） | 唯一 |
| 挂载点、设备 / 管道等其他类型、读取出错的条目 | 唯一 |
| 扫描后发生变化的文件（大小或修改时间与扫描时不同、或已不存在） | 唯一，并计入"已变化"统计 |
| 文件夹 | `D(按名字排序的 [(名字, 子项 token)…])`；任一子项唯一则文件夹唯一 |

- 名字按**原始字节**比较（区分大小写，不做 Unicode 规范化）。
- 硬链接本来就不额外占空间，所以既不算重复，也让包含它的文件夹"不可比"——宁可漏报，不误报。

### 5.2 忽略的系统文件

以下名字在**任何层级**都直接排除：不读取、不参与文件夹比较、不作为重复项列出，它们的子树同样排除。

`@__thumb`、`.@__thumb`、`@eaDir`、`.DS_Store`、`Thumbs.db`、以 `._` 开头的文件

### 5.3 列表规则（向上合并）

1. **重复文件夹组**：token 相同、成员 ≥ 2、内容大小 > 0 的文件夹。
2. **重复文件组**：完整校验值相同、成员 ≥ 2、大小 > 0 的文件。
3. 某个成员的**任一上级**是某个重复文件夹组的成员，就称它"已被包含"。
4. **一组的所有成员都已被包含时，这一组不列出**；否则列出，并列出它的全部成员（已被包含的成员标注"位于重复文件夹内"）。

示例：A、B 两个文件夹相同；A/x、B/x、C/x 三个文件相同，C 不在任何重复文件夹里。列出 `{A, B}` 和 `{A/x, B/x, C/x}`（后者标注 A/x、B/x 位于重复文件夹内），因为 C/x 仍是一份额外的拷贝。若 A、B 又各自位于相同的 P、Q 中，则 `{A, B}` 不列出，只列 `{P, Q}`。

### 5.4 大小与排序

- 每组记录"单份大小"：组内每个成员各自算一遍（文件夹 = 其中参与比较的文件之和），取**最小值**，磁盘占用 / 表观大小各一份，跟随界面上的"磁盘占用 / 表观大小"切换。
- 可释放 = 单份大小 ×（有效份数 − 1），有效份数 = 未被包含的成员数 + 被包含成员所属的不同最外层重复文件夹组数。没有成员被包含时就是"份数 − 1"；有成员被包含时，这样算可以避免和外层文件夹组的可释放重复计算（实现计划中补充的细化）。
- 排序：单份大小从大到小；相同时按可释放、再按第一个成员的路径。文件夹和文件混排。

## 6. 检查流程

新增子命令 `storage-analyzer dupcheck --scan <id>`，由界面通过接口拉起（与手动扫描同样的 `setsid` 方式）。

1. **加锁**：与扫描使用**同一把锁**（`run/scan.lock`），同一时间只跑一个重任务。定时扫描撞上正在进行的重复检查，照常跳过并记日志。启动后立即 nice 19 + IO 优先级 IDLE。
2. **读取扫描结果**：只读打开 `scan-<id>.db`。把所有文件夹的 (id, parent, name) 读进内存用于拼路径；用 meta 里的 `volumes` 把卷根 id 映射到挂载点。按 id 升序处理一遍得到"位于忽略目录下"的标记（子项 id 总是大于父项 id）。
3. **按大小分组**：普通文件、大小 > 0、非硬链接重复、非出错、非忽略 → 按表观大小分组，只保留成员 ≥ 2 的组作为候选。
4. **核对 + 查缓存**：对每个候选 `lstat`。大小或修改时间与扫描结果不同、或文件已不存在 → 记为已变化，退出候选。用 (路径, dev, inode, 大小, mtime, ctime) 查缓存，命中就直接用缓存里的校验值。
5. **快速比对**：未命中的候选读首尾各 64KB 计算快速摘要；不超过 128KB 的文件一次读完，快速摘要即完整校验值。按 (大小, 快速摘要) 再分组，落单的退出。
6. **完整校验**：剩下的读全文算 SHA-256，按 (大小, SHA-256) 得到最终的重复文件组。
7. **向上合并**：按 id 降序处理所有条目（相当于后序遍历），算出每个文件夹的 token，再按 §5.3 生成列表。
8. **写结果**：写入 `scans/dups-<id>.db.tmp`，成功后改名；更新 catalog；清理缓存（§7.2）。

**读盘方式**
- 完整校验一次只读一个文件，1MB 左右的顺序读；快速比对可以少量并行（随机小读，适度队列深度有利于 RAID）。
- Linux 上每读完一段调用 `posix_fadvise(DONTNEED)`，避免把 NAS 的页缓存冲掉。

**进度**（写入同一个 `run/progress.json`，新增 `job` 字段区分 `scan` / `dupcheck`）
- 阶段：准备 → 快速比对 → 完整校验 → 汇总；
- 本阶段已处理 / 总文件数、已读 / 需读字节数（这两个总数在阶段开始时已知，可以给出真实百分比）、缓存命中数、已变化数、当前文件路径。

**取消与中断**
- 沿用 SIGTERM 取消；未完成的结果文件删除，catalog 标为 `canceled`。
- 缓存**边算边提交**（例如每几秒或每几百个文件一次），所以取消或重启后再跑，已经算过的文件不再重读。
- `init-start` 中把残留 `running` 的检查标为 `failed`，清理 `dups-*.tmp`。

## 7. 存储

### 7.1 结果：`scans/dups-<scan id>.db`

示意结构（具体由实现决定）：

```
groups(
  id, kind,            -- 文件夹 / 文件
  name,                -- 第一个成员的名字（显示用）
  copies,              -- 份数
  files,               -- 文件夹组：每份里参与比较的文件数
  dsize, asize,        -- 单份大小（§5.4）
  rdsize, rasize       -- 可释放
)
members(group_id, entry_id, path BLOB, covered)   -- entry_id 指向 scan-<id>.db，用于跳转浏览
meta(key, value)       -- 开始 / 结束时间、读取字节数、缓存命中数、已变化数、出错数
```

指标：分页取一页（100 组）< 300ms；按两种大小模式排序都要快（给对应列建索引）。

### 7.2 缓存：`data/dupcache.db`

```
hashes(path BLOB PRIMARY KEY, dev, ino, size, mtime_ns, ctime_ns, quick BLOB, full BLOB NULL)
```

- 六个字段全部吻合才算命中；ctime 能识别 `cp -p` / `rsync -a` 保留了 mtime 的改写。
- 只缓存真正读过的文件（快速摘要，以及算过的话完整校验值）。
- **清理**：检查**成功完成**后，删除本次没有作为候选出现的路径。取消 / 失败时不清理。
- 缓存与扫描保留策略无关；卸载时随数据目录删除。

### 7.3 catalog

新增表（或等价结构）：

```
dupchecks(scan_id PRIMARY KEY, status, started_at, finished_at, duration_s,
          groups, reclaim_dsize, reclaim_asize, bytes_read, cache_hits,
          changed, errors, error_message)
```

- 每次扫描最多一份检查结果；对同一扫描重新检查会覆盖。
- 删除扫描（手动或保留策略）时连同 `dups-<id>.db` 和这一行一起删除。

## 8. 接口

| action | 方法 | 作用 |
|---|---|---|
| `dup_start` | POST | 参数 `scan`；拉起 `dupcheck --scan <id>`。已有任务在跑 → 409；扫描不存在或未完成 → 404 |
| `dups` | GET | 参数 `scan`、`size`（disk / apparent）、`offset`、`limit`；返回该扫描的检查状态与汇总、总组数、一页组（每组带成员，单组最多返回 100 个成员并给出总数） |
| `status` | GET | 进度里增加 `job`、`phase` 及 §6 中的字段 |
| `scans` | GET | 每次扫描附带其重复检查的状态与可释放大小（供历史列表显示） |
| `scan_cancel` | POST | 取消当前任务（扫描或重复检查） |
| `scan_delete` | POST | 正在被检查的扫描不允许删除（409） |

鉴权、POST 头校验与现有接口一致。

## 10. 测试

**本地单元测试**
- 合并规则（纯函数，输入内存中的树 + 校验值）：嵌套相同文件夹合并到最外层；§5.3 的部分包含示例；文件名不同 / 多一个文件 / 结构不同 → 不相同；外层文件夹名字不同 → 仍相同；忽略的系统文件不影响判定；只含空文件 / 空文件夹的文件夹不列出；硬链接重复、挂载点、已变化文件让上级文件夹不可比；0 字节文件不单列；排序。
- 比对（临时目录里的真实文件）：大小相同但只有中间不同 → 不相同；不超过 128KB 的小文件；扫描后改过 → 排除并计数；缓存命中时不读文件（通过可注入的打开函数计数）；mtime / 大小 / ctime 任一变化 → 缓存失效；取消后缓存保留已算部分。
- 接口：`dup_start` 冲突 409；`dups` 分页与排序；删除扫描时连带删除检查结果；正在检查的扫描不可删除。

**设备上端到端（hf-qts）**
- 对 DataVol1 跑一次完整检查：记录耗时、读取字节数、峰值内存、结果文件大小；检查期间 NAS 正常响应。
- 不改数据立刻再跑一次：确认几乎全部命中缓存、耗时大幅缩短。
- 中途取消再跑：确认已算部分不重读。
- 检查进行中触发定时扫描：确认被跳过并记日志。
- 浏览、展开、跳转、窄屏无横向滚动。

## 12. 本文档中由 Claude 做出、待用户确认的决定

1. 0 字节文件和硬链接不算重复；含硬链接重复条目的文件夹不参与文件夹比较。
2. 排序按单份大小从大到小，另显示"可释放"；单份大小跟随"磁盘占用 / 表观大小"切换，取组内最小值。
3. 一组只有在所有成员都已被重复文件夹包含时才隐藏（§5.3）。
4. 忽略 `@__thumb`、`.@__thumb`、`@eaDir`、`.DS_Store`、`Thumbs.db`、`._*`：不读、不比较、不列出。
5. 文件名按原始字节比较，不做 Unicode 规范化、区分大小写。
6. 符号链接按链接目标比较。
7. 重复检查和扫描共用一把锁；检查期间的定时扫描会被跳过。
8. 扫描后有变化的文件不参与比较，只在汇总里提示数量。
9. 校验值缓存只在检查成功后清理，清理掉本次未作为候选出现的路径。
10. 界面用 [空间占用 | 重复项] 视图切换，而不是弹窗。
